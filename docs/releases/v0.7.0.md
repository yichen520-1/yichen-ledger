# 忆尘记账 v0.7.0

这一版做了三件事，一件比一件更「不只是记账」：

1. **一个 App 拆成两个。** 「忆尘记账」和「忆尘日程」各有自己的图标，
   并排站在侧边栏里；手机上在底部导航互相串门。
2. **日程里长出一张课表。** 七列星期 × 节次的网格，单双周、周次、开学日期都算得清；
   拍张照就能把课表录进来。
3. **忆小尘的入口会跑了。** 那颗按钮按住就能拖，松手自己吸到最近的边上。

---

## 一、为什么要拆成两个 App

原来的做法是一个胶囊形开关「记账 / 日程」，点一下整站换一套导航。

问题是：**它看起来像一个筛选器，而不是两个应用。**

用户截图里那句「这个不要，改掉」，指的就是它。胶囊上写着两个词，
你得先读一遍才知道点下去会发生什么；而手机上一个真正装着两个 App 的人，
看到的是**两个图标**——图标不用读，认得出来。

所以这一版：

| | 桌面端 | 手机端 |
| --- | --- | --- |
| 长什么样 | 侧边栏顶部两枚 40×40 的图标并排，下面一行小字 | 底部导航里只放**另一个** App 的图标 |
| 点一下 | 整个工作区切过去 | 整个工作区切过去 |

**手机上为什么只露一个图标？** 底部导航有五个格子（总览 / 统计 / + / 预算 / 设置）。
再塞两个 App 图标进去，文字会被挤到 10px 换行。所以只显示「另一个」——
你已经在记账里了，需要的只是「去日程」，那个入口就是日程的图标。

图标底下那行小字（「忆尘记账」「忆尘日程」）只出现在桌面端：
侧边栏有地方，而且桌面上图标更小，需要文字补足辨识度。

## 二、江南风的新图标

忆尘日程需要一个自己的图标，要求是「和现在这个软件的图标相似，但是江南风」。

原来那枚是水墨的：一方砚台似的深色底，上面几笔淡墨。新的这枚延续同一套气质，
但把画面换成了江南：

- **白墙黛瓦** —— 两段马头墙，一高一低，墙是暖白，瓦是焦墨；
- **一叶小舟** —— 停在墙根的水面上，船身一道弧线，橹是斜的；
- **烟雨** —— 三层极淡的横向雾带，把远景推远；
- **朱红「程」印** —— 右下角一枚小方印，是整套图标里唯一的高饱和色。

「程」这个字是特意挑的：既是「日程」，也是「一程山水」。
印章用的是朱红，和忆尘记账那枚的墨色形成冷暖对照——两枚并排时能看出是一家人，
又不会认错。

画这个图标没有用设计软件，是 `scripts/make_icon_schedule.py` 用 PIL 一行行画出来的
（334 行，含贝塞尔近似的水波纹和马头墙的层叠）。好处是**可复现**：
改一个常量就能出全套尺寸，`scripts/make-schedule-icon.py` 负责导出
`public/schedule-badge.png`（导航用）、`schedule-192.png`、`schedule-512.png`、
`schedule-touch-icon.png` 和 `docs/screenshots/icon-schedule.png`。

## 三、忆小尘会跑了

原来那颗按钮钉死在右下角。问题很具体：**统计页的右下角正好是最后一根柱子**，
预算页的右下角是进度条的尾巴。按钮压着数据，用户要么忍着，要么滚一下。

现在按住它就能拖：

- 拖到哪儿松手，**自动吸到最近的左边缘或右边缘**。
  为什么不做完全自由：停在屏幕正中间会一直压着内容，贴边之后内容区永远是完整的——
  iOS 的悬浮球、微信的悬浮窗都是这个选择。
- 纵坐标存的是**比例**（0~1），不是像素。换个屏幕尺寸、转个屏，按钮还在相对高度差不多的位置，
  不会跑到屏幕外。
- 拖动超过 6px 才算「拖」，否则算「点」——手指按下去抖一下不该被当成拖动，
  也不该因为拖过又松手就误开面板。
- 用 Pointer Events 而不是 mouse/touch 两套：一套代码同时覆盖鼠标、手指和笔，
  而且 `setPointerCapture` 之后即使手指滑出按钮，移动事件还发到这个元素上——
  不然拖快了指针一离开按钮，拖动就断了。

位置和外观设置一样存进 IndexedDB。清库时一起清掉，不会出现
「账没了但按钮还飘在奇怪的地方」。

## 四、课表

这是这一版最大的一块。它不是一个新页面，而是「忆尘日程」里的第二个标签：

```
忆尘日程
  ├── 日程   ← v0.3.0 就有的月 / 周 / 日
  └── 课表   ← 这一版新增
```

标签用 `history.replaceState` 而不是路由跳转，所以切标签不会在浏览历史里堆一层——
手机返回键应该回到上一页，而不是回到上一个标签。

### 网格怎么画的

左边一列是节次（第 1 节、第 2 节……），右边七列是星期一到星期日。
用 CSS Grid：`grid-template-columns: 44px repeat(7, minmax(66px, 1fr))`。

手机上七列放不下，所以整张表可以横向滚动，节次列 `position: sticky` 钉在左边。
**节次列必须钉住**——不然滚到周五的时候，你已经不知道那一行是第几节了。

一门课跨几节，就用 `grid-row: span N` 撑开。课块用
`color-mix(in srgb, var(--c) 22%, transparent)` 上色、左边一道 3px 的实色条：
这样同一个颜色在深色和浅色主题下都够淡（能看清字），但色条始终是准的（能认出来是哪门课）。

### 周次与单双周

课表最容易搞错的是「第几周」。这一版把它算成纯函数（`src/domain/timetable.ts`）：

- `weekNoOf(termStart, dateKey)` —— 今天第几周，开学那周算第 1 周；
- `parityMatches(parity, weekNo)` —— 单周 / 双周 / 每周；
- `sessionActive(session, weekNo)` —— 这一节这周上不上（周次范围 + 单双周一起判）。

一条课程时段长这样：

```ts
{ weekday: 3, startPeriod: 3, endPeriod: 4,
  parity: 'odd', weekFrom: 1, weekTo: 15 }
```

读作「每周三第 3~4 节，单周上，第 1 周到第 15 周」。
界面上写成「周三 3-4 节 · 单周 · 1-15 周」，不需要用户理解上面那行代码。

### 冲突检测

两门课在同一时间同一节次（且单双周有交集）就会在页面上方提示。
判断的是 `findConflicts(courses)`，也是纯函数——所以有单测，不用手点。

**没有做「阻止保存」。** 现实里课表就是会冲突（选修课、实验课、临时调课），
拦着不让存只会让人放弃用这个功能。提示出来，让人自己决定。

### 从图片建课表

两条路，和 v0.3.0 的日程 OCR 一样：

| | 填了 API Key | 没填 |
| --- | --- | --- |
| 怎么识别 | 云端多模态，**要求返回 JSON 数组** | 本机 tesseract.js，规则解析 |
| 为什么 | 一门课有多个时段，纯文本会把结构压平 | 不联网、不出设备 |

云端那条特意写死了 JSON 的 schema：一门课是
`{name, teacher, location, sessions: [{weekday, startPeriod, endPeriod, parity, weekFrom, weekTo}]}`。
如果让它返回一段自然语言，前端还得再解析一遍自然语言——那等于把问题推给了下一层。

本机那条用 `src/domain/timetableOcr.ts`：找星期（「周一」「星期一」「Mon」）、
找节次（「1-2 节」「第 3、4 节」）、找周次（「1-16 周」「单周」），
再把同一行的课名、老师、地点拆开。规则解析当然不如大模型，但它**离线可用、结果可预期**。

解析出来的不是直接入库，而是**候选列表**：每条都能勾掉，低置信度的标黄。
确认之后才写库，重名课程可以选择覆盖。

## 五、顺手修掉的两个真 bug

这两个都是这一版开发中撞出来的，**都会让 App 完全不可用**，值得单独记一笔。

### 1. 全新安装会永远卡在「正在准备账本…」

`src/state/LedgerContext.tsx` 里新加了一个查询：

```ts
useLiveQuery(() => db.settings.get('timetable.meta'))
```

问题在于 `useLiveQuery` **无法区分「还没读出来」和「查出来就是 undefined」**。
全新安装时这个键还不存在，查出来就是 `undefined`，
于是「还没准备好」的判断永远成立，`ready` 永远是 `false`，App 永远停在加载页。

修法是让查询体永远返回一个非 undefined 的值：

```ts
useLiveQuery(async () => (await db.settings.get('timetable.meta')) ?? null)
```

这是个**回归**——v0.6.0 没有这个查询，所以之前的自检脚本全绿。
抓到它靠的是「删库重新打开」这一条路径，而不是在已有数据的 profile 上刷新。

### 2. 刷新会丢掉「课表」标签

直接打开或刷新 `#/schedule?tab=timetable` 时，页面会被弹回总览。

原因是模式对齐的 effect 跑得太早：`ui.mode` 是从 IndexedDB **异步**读出来的，
第一帧一律是 `'ledger'`。这时候路径是 `/schedule`，于是
「在记账模式下却停在日程页」的判断成立 → `navigate('/', { replace: true })`。
等模式读完再跳一次 `/schedule`，标签页已经丢了。

修法是在 effect 开头加一道闸：

```ts
if (modeLoading) return;
```

**等模式读完再对齐。** 这条和课表本身没关系，但课表是第一个会被人收藏成链接的页面
（「打开就是我的课表」），所以它先暴露出来。

## 七、升级注意

- **数据库从 v2 升到 v3**：只加了一张 `courses` 表，没有改任何已有的表。
  账目、账户、分类、预算、日程一条都不会动。
- **备份格式升到 v3**：多了一个 `courses` 字段。旧备份仍然可以导入（缺的字段当空处理）；
  新备份在 v0.6.0 及更早的版本里导入会丢掉课表——但账本部分照常。
- **外观设置不受影响**：`ui.mode` 的取值没变，还是 `'ledger'` / `'schedule'`。
- **悬浮球位置是新的键**（`ui.fab.pos`），老用户第一次打开时是出厂的右下角。
