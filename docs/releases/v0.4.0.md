# 忆尘记账 v0.4.0

这一版的主题是**「让它能听懂你说话」**。

v0.2.0 把界面做全了，v0.3.0 把日程装进来了，v0.4.0 补上最后一块：
**忆小尘** —— 一个住在 App 里的助手，两个身份，同一个对话框。

| | 忆小尘 · 账 | 忆小尘 · 程 |
| --- | --- | --- |
| 管什么 | 钱 | 时间 |
| 在哪出现 | 总览页、统计页右下角 | 日程页右下角 |
| 能答什么 | 这个月花了多少 / 哪一类最多 / 预算还剩多少 / 我现在有多少钱 / 哪一类涨得最快 | 这周有几个日程 / 周五下午有空吗 / 接下来是什么 |
| 能做什么 | 「记一笔午饭 25」→ 确认后落库 | 「提醒我周三下午三点交报告」→ 确认后建日程 |

> **数据不动。** v0.4.0 一行数据库 schema 都没改，没有版本升级，
> 打开就是原样。它只是在原有数据上多了一层「用中文问」的入口。

---

## 一、为什么要做这个

记账 App 最真实的死因不是功能少，是**懒得记**。之前已经把「记一笔」压到了三步（点数字 → 点分类 → 保存），
但还有一层摩擦：你得先想清楚「这笔该归到哪个分类」。

于是就有了这个想法：**如果你只是想说一句「午饭 25」，那就让你说一句话。**

同一套逻辑顺手解决了另一半：查账也是。翻统计页看分类占比是一种方式，
但很多时候你只想知道「这个月花了多少」，那就不该逼你点三个页面。

## 二、混合式：本地规则打底，云端可选升级

这是这一版最重要的一个设计决定。

| 情况 | 走哪条路 | 特点 |
| --- | --- | --- |
| **没填 API Key**（默认） | 本机规则引擎 | 纯函数、零网络、零延迟、不上传任何数据 |
| **填了 API Key** | 云端大模型 | 能听懂自由说法，回答更自然 |

关键在于**两者共用同一个对话框**，界面上只有一个徽标在变（「本地规则」↔「云端 · deepseek-chat」）。
你不需要提前选择模式，填了 Key 它自己就升级了。

### 云端挂了会怎样

**不会给你一句「请求失败」。** 顺序是这样的：

1. 本地规则先算一遍（所以答案一定存在）
2. 有 Key 就再问云端
3. 云端成功 → 用云端的回答
4. 云端失败 → 显示「云端没答上来（原因），下面是本地算的结果。」+ 本地答案

也就是说，**断网、Key 过期、余额不足、服务商挂了，你依然能查账、能记账**。
这条兜底不是事后补的，是写进流程的：`send()` 里本地计算永远在云端调用之前完成。

### 隐私边界

- 本地规则引擎是 `src/domain/assistant.ts` 里的**纯函数**，入参只有账本快照，出参只有结构化结果，不碰网络
- 填了 Key 之后，每次提问会把**当前账本的摘要**（净资产、本月收支、分类排行、预算状态）拼进 system prompt 一起发出去
- 发出去的是摘要，不是全量流水；但仍然是真实数据，**所以 Key 和隐私这件事请你自己判断**
- API Key 只存在本机 IndexedDB，不进备份文件、不上传

## 三、忆小尘 · 账

### 能答的

| 你问 | 它答 |
| --- | --- |
| 这个月花了多少 | 这个月花了 ¥1,234.56，一共 42 笔。 |
| 昨天花了多少 | 昨天花了 ¥86.00，一共 3 笔。 |
| 上个月吃饭花了多少 | 上个月在「餐饮」上花了 ¥980.00，一共 31 笔。 |
| 哪一类花得最多 | 这个月花得最多的是「餐饮」，¥1,234.00，占 42%。后面依次是… |
| 哪一类涨得最快 | 和 2026-09 比，涨得最多的是：餐饮 +¥320.00、交通 +¥80.00 |
| 预算还剩多少 | 2026-10 的预算：总预算 ¥5,000 / 已用 ¥3,200 / 64%；餐饮 超支 |
| 下个月预算定多少合适 | 按最近 3 个月的平均，下个月大概 ¥4,800 比较合适。 |
| 我现在有多少钱 | 现在净资产 ¥12,345.00。钱主要在这些地方：银行卡 ¥8,000、支付宝 ¥4,000… |
| 支付宝还有多少 | 「支付宝」现在有 ¥1,234.00。 |
| 最近 6 个月趋势 | 最近 6 个月的支出：2026-05 ¥3,100、2026-06 ¥2,900… |
| 这周花了多少 | 这周花了 ¥320.00，一共 8 笔。 |

时间说法支持：今天 / 昨天 / 这周 / 上周 / 这个月 / 上个月 / 今年 / 去年 / 最近 N 天 / 最近 N 个月 / 具体某月 / 全部时间。

分类靠**同义词表**匹配：说「吃饭」「外卖」「下馆子」都能落到「餐饮」，说「打车」「地铁」落到「交通」，
说「房租」「水电」落到「居住」。匹配不到就按全部支出算，不会硬塞一个错的分类。

### 能做的：记一笔

说「记一笔午饭 25」「午饭 25 支付宝」「昨天打车 30」「收入 5000 工资」，它会先**摆出来给你看**：

> 要记这样一笔吗：2026-10-28 · 餐饮 · 现金 · 支出 ¥25.00 · 午饭
>
> 　[就这样记]　[不用了]

**你不点，它就不写库。** 这是刻意的：自然语言解析一定会有错的时候，
让 AI 直接改你的账本是不可接受的；让你看一眼再确认，成本只有一次点击，但心里有底。

确认之后气泡变成「记好了。」，总览的净资产立刻跟着变。

金额必须带「元 / 块 / ￥」或者紧跟在分类词后面 —— 「记一笔 3」这种分不清是 3 元还是 3 笔的，它会拒绝猜。

## 四、忆小尘 · 程

在日程模式下，同一个按钮换个身份出现，标题变成「忆小尘 · 程」。

### 能答的

| 你问 | 它答 |
| --- | --- |
| 这周有几个日程 | 这周有 5 项日程。 |
| 今天有什么 | 今天有 2 项日程…（带时间与标题） |
| 周五下午有空吗 | 2026-10-30 的空闲时段：13:00–15:00、16:30–18:00（那天已经占了：周会 09:00–10:00） |
| 接下来是什么 | 接下来是这些：… |
| 这个月有几个日程 | 这个月有 18 项日程。 |

空闲时间算法：把当天的日程按时间排开，在 **09:00–22:00** 这个白天区间里找**连续 30 分钟以上**的空档。
排满了会明说「白天基本排满了」，不会硬凑一个空档出来。

### 能做的：加日程

说「提醒我周三下午三点交报告」「明天上午十点开会」「加个日程 周五 14:00-15:30 设计对稿」，
同样是先摆出来确认，点「就这样记」才真的建。

日期支持：今天 / 明天 / 后天 / 前天 / 周几 / 下周几 / 具体某月某日；时间支持：三点、下午三点、15:30、14:00-15:30。
说不清时间的就建成**全天**日程，不会瞎猜一个点。

## 五、界面上的一些细节

- **入口只在三个页面出现**：总览、统计、日程。记账页故意不显示 —— 那里有数字键盘，右下角再浮一个按钮会挡手
- **切模式对话不丢**：从记账切到日程，之前聊的内容还在（因为状态提到了 `AssistantProvider` 里）。想重开就点顶部的「重新开始」
- **示例问法随模式变**：记账模式给的是「这个月花了多少 / 哪一类花得最多 / 预算还剩多少」，
  日程模式换成「这周有几个日程 / 周五下午有空吗」
- **手机上从底部升起，桌面上是右下角卡片**：手机 `height: min(78vh, 640px)` 圆角顶盖，
  ≥900px 变成 420px 宽的浮动卡片，遮罩层透明且不挡鼠标
- **弹层挂在 `document.body` 上**：和 v0.2.0 的 Sheet 一样，用 portal 绕开页面切场动画的 `transform` 包含块问题
- **Enter 发送、Shift+Enter 换行、Esc 关闭**

## 六、修掉的两个真问题

1. **「我现在有多少钱」被当成花销问题**
   「多少钱」这个词同时出现在「这个月花了多少钱」和「我现在有多少钱」里，
   而花销分支先匹配，于是净资产问题被算成了本月支出。
   修法是在花销分支之前先接住净资产（`净资产|总资产|有多少钱|还有多少钱…`），并写注释说明顺序不能换。

2. **「提醒我明天交房租」落到了今天**
   日期解析只认「今天 / 昨天 / 这周 / 下周」，没有「明天 / 后天 / 前天」。
   补上之后按偏移量算日期（后天 +2、前天 -2、明天 +1），复用单日区间的形状返回。

## 七、升级注意

- 装新版本直接覆盖，**不需要先卸载**，也不需要迁移数据（schema 没动）
- 网页版换了新的 Service Worker 缓存名（v4 → v5），打开后如果还是旧界面，刷新一次就好
- 助手默认走本地规则，**不填 Key 就是完整可用的**；想试云端就在「设置 → AI」里填
- 不想要这个按钮也没有开关 —— 它只在三个页面右下角，不影响任何原有操作路径

## 八、下一步

v0.1 → v0.4 这条线走完，这个 App 已经从「一个记账工具」变成了「一个本地优先的个人小助手」。
后面还能做的，按投入产出排：

| 方向 | 为什么值得做 |
| --- | --- |
| **语音输入** | 手机上最顺的记账方式，Web Speech API 就能接，和忆小尘是天然一对 |
| **周期性账单自动生成** | 房租 / 话费 / 会员占了支出大头，自动生成能免掉一半动手 |
| **月度报告图** | 唯一能让人主动截图分享、帮你带来新用户的功能 |
| **端到端加密同步** | 现在四端数据各存各的，同步是长期需求 |
| **生物识别锁** | 账本是很私密的数据，Face ID / 指纹 / Windows Hello |

任何一条你想先做，说一声就行。
