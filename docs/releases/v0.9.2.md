## 二、再把没用的东西清掉

清理的判据只有一条：**全项目（源码 + 测试 + 自检脚本）搜这个名字，只有定义那一行，没有任何调用**。
不确定的一律不动——「看着像没用」不等于没用。

### 1. 数据层：16 个死查询函数

`src/db/repository.ts` 从 30402 字节降到 26791 字节（**-3611**）。

删掉的 16 个：`initDb` / `listAccounts` / `listCategories` / `listTransactions` /
`listBudgets` / `listEvents` / `listCourses` / `loadTimetableMeta` / `listRules` /
`listPendingBills` / `ruleDates` / `listQuickTemplates` / `deleteQuickTemplate` /
`listReceipts` / `listAllReceipts` / `deleteReceiptsOf`。

**为什么确定没人用**：这些是 v0.1~v0.9 各阶段写数据层时顺手加的「列表查询」入口。
但界面从头到尾走的是 `LedgerContext` 里的 `useLiveQuery`（Dexie 的实时订阅）——
数据一变界面自己就更新，根本不需要手动 `list*()` 再塞进 state。
两套东西同时存在，只会让下一个读代码的人以为有两条路径。

另外 7 个（`TransactionDraft` / `ErrorCode` / `ValidationError` / `validateDraft` /
`validateEventDraft` / `validateCourseDraft` / `validateRuleDraft`）**只是去掉 `export`**——
文件内部还在用，不需要对外暴露。

### 2. 领域层：11 个死导出

### 3. 样式：2 条死规则 + 4 个死变量

`src/styles.css` 从 89657 字节降到 89011 字节（**-646**）。

- `.sched-tabs` —— v0.7.1 把日程页右上角那排胶囊标签改成路由，容器规则没人用了。
  **`.sched-tab` 刻意保留**：`schedule-check.mjs` 里有一条断言「页面里不再有胶囊标签」，
  靠数它的数量来验证，删了断言就失效。
- `.badge-pending` —— 待收页用的是 `.badge-settled`；未结清的本来就整条列在
  「待收的钱」下面，不需要再打一个「待收」徽章。
- `--glass-sheen-2`（深色/浅色两处）—— 定义了但零引用。
- `--fab-bg`（深色/浅色两处）—— v0.6.0 把悬浮球从「深色圆片」改成玻璃球后废弃，
  注释里还专门写着「之前用的是 --fab-bg」。

### 4. 文案：82 个死键 × 三种语言

`src/i18n/{zh,en,ja}.ts` 各从 **857 键降到 775 键**，三份依然完全一致（`tsc` 验证）。

分布：add 2 / assistant 5 / categories 1 / dashboard 2 / event 5 / lock 10 /
quick 8 / receipt 8 / receivable 1 / recurring 6 / review 3 / schedule 9 /
search 5 / settings 6 / timeline 1 / weekly 1 / annual 9。

两类：
- **设计时备选的文案**，最终界面没用到（例如 `lock.pinWeak` 想显示「这个密码太简单」，
  但实际做法是直接拦下来不让设，不需要提示语）。
- **页面后来改版**，旧文案留下了（例如 `recurring.monthlyEquivalent`
  原本想在列表里显示「折合每月 ¥3500」，后来改成只在汇总卡片显示一次）。

**怎么确认没删错**：把 zh.ts 求值摊平出全部叶子键，再扫 `src/` 下所有 `t('xxx.yyy')`
调用逐个比对；另外单独检查了 `t(\`xxx.${...}\`)` 这类动态拼接的前缀（如 `common.${type}`、
`errors.${code}`），这些前缀下的键一个都没删。`weekLong` / `weekShort` 是顶层数组，
通过 `dict.weekLong` 访问，也不在删除范围。

## 五、这一版没做的事

以下几件我判断「现在不该动」，写在这里免得下次重新讨论：

- **依赖没动。** 审计时看过 `npm ls`，没有多余的直接依赖——看着「没 import」的几个
  （`@capacitor/*`、`electron-builder`、`concurrently`、`wait-on`）都是构建/CLI 在用；
  `@capacitor/local-notifications` 和 `tesseract.js` 是 `await import()` 动态加载的。
  升级依赖是另一件事，混在清理里会让「是不是这次改坏的」说不清。
- **文件没合并。** 有几个组件只有几十行（`BackButton`、`Toast`、`Sheet`），
  合并进调用方确实能少几个文件，但会破坏「一个组件一个文件」的读法。
  文件数量不是负担，找东西的成本才是。
- **注释没删。** 项目里注释偏多，但都是有理由的那种（为什么这么选、当初踩了什么坑），
  不是「// 设置 state」这种复述代码的废话。
